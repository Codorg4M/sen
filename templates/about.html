Software Engineering Project Specification

Academic Documentation & Architectural Overview of RideShare – College-level Mini Project.

1. Project Objectives & Problem Statement

Urban and college campus commuters frequently travel along identical corridors with single-occupancy vehicles, resulting in high travel expenses and unnecessary congestion. RideShare provides a functional, decentralized web platform allowing verified drivers to list available vehicle seats and riders to search, book, and commute economically.

2. System Actors & Roles

👤 Rider: Registers, searches available rides using location/date filters, submits seat booking requests, tracks confirmation status, cancels pending bookings, and views ride history.
🚗 Driver: Registers with vehicle specification & driving license, creates ride listings, reviews incoming passenger requests, accepts/rejects bookings with automatic seat allocation, and marks trips completed.
🛡️ Administrator: Oversees system health, monitors all platform users, activates/deactivates accounts, reviews all rides/bookings, and moderates content.

3. State Machine & Transitions

Ride Lifecycle

  • Available ➔ Initial post state with seats > 0.
  • Full ➔ Auto-triggered when remaining seats = 0.
  • Completed ➔ Driver marks journey finished.
  • Cancelled ➔ Driver cancels trip (notifies riders).

Booking Lifecycle

  • Pending ➔ Rider requests seats.
  • Accepted ➔ Driver accepts (seats deducted).
  • Rejected ➔ Driver rejects (seats preserved).
  • Cancelled ➔ Rider cancels (seats refunded).
  • Completed ➔ Journey marked completed.

4. Fare Estimation Formula

Formula: Estimated Fare = Base Fare + (Distance in KM × Rate per KM)
Default Parameters: Base Fare = ₹30.00 | Rate per KM = ₹12.00

* Notice: Fare calculation is strictly a simulated demonstration value for academic evaluation and does not connect to real financial gateways.
